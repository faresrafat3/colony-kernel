20. Atomic-effects fix (2026-10-29). A budget command wrote its ledger row before the transition was checked: on an ABORTED mission, `reserveBudget` returned `ILLEGAL_TRANSITION` while the row kept `reserved=10` and the event log recorded nothing. `settle` and `release` shared the shape, `applyBudgetTopUp` consumed the approval before a commit that could still fail, and `requestPlanApproval` / `requestPackageApproval` wrote the gate request after the commit, so a crash between the two left a gate nobody could answer. `atomicApply` now takes an optional `effects` callback that runs after the events reduce and before the commit returns; a throw restores events, state and every effect already written. Audit facts (approval records, rejections, finalized artifacts) stay outside the transaction because they must survive a refusal. Three contract tests in `tests/contracts/atomic-effects.test.ts`: an effect failure rolls back events, state and rows; a refused reserve spends nothing and records one rejection; a refused top-up consumes no approval and does not move the limit. Test count 147 → 150; the demo output is byte-identical (same event-log hash and `262d937b…` file hash).

21. Seam-guard fix (2026-10-29). An audit of the application layer found six must-fix gaps, now pinned by tests: (a) a pending plan approval could authorize the publish gate — a decision now requires the request's purpose, from-state and state version to match the open gate (C-12/C-13); (b) a gate request could name no artifacts or another mission's artifact — each subject must be this mission's finalized artifact with matching type/hash/time, and the bound plan (or candidate+verification) must be present (C-14, I-02); (c) the approver deny-list was the test manifests rather than the injected registry — it is now `roleIds()` (the F1 suite's custom-registry case); (d) a top-up accepted negative or fractional amounts — positive integers only, with `assertLedgerInvariants` asserted on the result (E-06b); (e) an expired approval returned as APPROVED on replay — now refused (C-11); (f) any role could finalize any artifact type — the capability manifests now gate production (F2). Test count 150 → 157; the demo output is byte-identical (same event-log hash and `262d937b…` file hash).

22. Lease TTL fix (2026-10-29). `InMemoryColonyStorage.acquireLease` ignored `expiresAt`, so a crashed writer held the single-writer name forever. It now treats an expired lease as free (the boundary instant included) and refuses an unparseable `expiresAt` with `INVALID_SCHEMA`; the adapter takes the injected clock, and the demo and test kit pass the same clock the kernel uses. I-05 advances a mutable clock past the TTL. Test count 157 → 158; the demo output is unchanged.

23. Lease renewal (2026-10-29). The spec's N7 lists `renewLease` but the port and adapter omitted it. `renewLease(name, ttl)` now extends a live lease, refuses an absent or expired one with the new `LEASE_NOT_HELD` code, and validates the timestamp like `acquireLease`. I-06 covers extension, expiry, absent and malformed cases. Test count 158 → 159; the demo output is unchanged.

24. Sequence allocator (2026-10-29). `reserveMissionSequence` returned the state's next sequence on every call, so two reservations could receive the same number. It now keeps a per-mission counter (max of committed and reserved, plus one), deliberately outside the `atomicApply` snapshot so a rollback cannot reissue a number; gaps are legal. I-07 covers consecutive calls, a commit in between, and an unknown mission. Test count 159 → 160; the demo output is unchanged.

25. CAS signature (2026-10-29). The spec's N7 CAS takes `(missionId, expectedVersion, nextState, events)`; the port and adapter dropped `events`, so a durable adapter could not commit an append with the swap. The signature now matches: the events are appended under the same unique constraints as `appendEvent` (one shared helper), the state/event batch must agree (version and sequence advance by the batch length), and any mismatch returns without writing. I-08 covers the happy path, a stale version and a mismatched batch. Test count 160 → 161; the demo output is unchanged.

26. Expiry pause (2026-10-29). The spec's state table sends an expired gate to HUMAN_REVIEW_REQUIRED (E13/E29), but the kernel only rejected the decision and left the mission at the gate. After the durable EXPIRED_AT_COMMIT rejection, the kernel now commits a durable APPROVAL_EXPIRED event; the pause records its pre-pause stage, so a human resume re-enters the gate, and C-15 covers the pause, its no-automatic-work rule, the resume and a successful reissue. Test count 161 → 162; the demo output is unchanged.

27. Top-up approval terms (2026-10-29). A BUDGET_TOPUP approval carried no amount or class, so one approval could move any amount on any allowed class, with no expiry check at consumption. `ApprovalRequest` gains an optional `budgetTopUp` field (inside the subject hash; additive, `schemaVersion` 1, documented in `docs/SPEC_DEVIATIONS.md` §8); `requestBudgetTopUp` records the terms (positive integer, allowed class, known requester) as an approval artifact without a mission event (N10 has no APPROVAL_REQUESTED edge outside the gates); `applyBudgetTopUp` refuses a class/amount mismatch (INVALID_PURPOSE), a mutated request (STALE_APPROVAL) or an expired one (EXPIRED_AT_COMMIT). E-10/E-11/E-12 cover binding, expiry and staleness; the three seeded test helpers carry matching terms. Test count 162 → 165; the demo output is unchanged.

28. Sealed kernel storage (2026-10-29). `ColonyKernel.storage` was public, so any holder could call `recordApprovalDecision`, `appendEvent` or `createApprovalRequest` and bypass every seam guard; stored requests could also be replaced in place. The field is private now — the host keeps the instance it injected (the demo and test kit do) and reads through the port. `createApprovalRequest` is immutable: identical bytes are an idempotent replay, different bytes are `APPROVAL_CONFLICT`. C-16 pins it; R1/E-12 simulate a non-conforming adapter with a tampering storage wrapper, since a conforming one can no longer mutate a request. Test count 165 → 166; the demo output is unchanged.

JCS astral-key order (2026-10-29). `canonicalJson` sorted keys by Unicode code points, not UTF-16 code units, so a key outside the basic plane (an emoji) ordered wrongly against a high-BMP key and produced a non-RFC-8785 hash. It now uses the language's string sort (UTF-16 code units) and the custom comparator is gone; an adversarial vector pins `{"😀":1,"\uFFFD":2}`. Test count 166 → 167; the demo output is unchanged (all its keys are ASCII).
