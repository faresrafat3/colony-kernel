# Separate pause-return target from revision-return target

A Mission's single `resumeStage` field was overloaded for two different jobs: it recorded the pre-pause stage for recovery re-entry, and it also recorded the stage to return to after a revision cycle. Because both writes went through one field, entering a pause during a revision cycle overwrote the revision's return target, and a revision started while paused corrupted pause bookkeeping. The two concerns are now stored in separate state fields (`resumeStage` for pause return, `revisionReturnStage` for revision return), and neither mutator may touch the other's field. The trade-off is a small, permanent enlargement of the persisted MissionState shape (schemaVersion 1) against the loss of rework routing information under the single-field design.
